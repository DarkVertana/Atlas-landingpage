# SEO Audit & Implementation Report — Atlas Screening Website

**Date:** 2026-08-13 | **Domain:** https://atlasscreening.com
**Stack audited:** Next.js 16.2.3 (App Router, Turbopack), React 19, Tailwind 4
**Method:** static code audit + rendered-page crawl of all 35 routes on localhost
**Result:** see Section 9 — implemented fixes are live in the repo and build-verified.

---

## 1. Executive summary

The site had a solid metadata baseline (every route had a title + description) but
was missing nearly all of the technical SEO layer. Before this pass: **zero
JSON-LD, zero OG/Twitter tags (except blog posts), zero canonical tags, no
sitemap.xml, no robots.txt, no manifest, nine routes without an H1, masked
telephone links, and four FCRA-sensitive claim phrasings.** All issues found are
now fixed; the production build passes with 35 routes.

| Area | Before | After |
|---|---|---|
| Routes returning 200 (fresh server) | 31/35 (4 infra 404s) | 35/35 |
| H1-per-page | 9 routes missing | 0 missing (exactly one each) |

| OG/Twitter tags | blog posts only | All routes |
| JSON-LD | 0 blocks | 16+ blocks (Org, WebSite, Service×9, FAQPage×2, BlogPosting×9, Breadcrumbs) |

## 2. Technical crawl findings (all routes)

### 2.1 HTTP status — all 200 (after server restart)
The previously-404ing routes (`/services/*`, `/resources/*`, `/blog/[slug]`,
`/admin`) were **stale dev-server artifacts**: Turbopack was watching the wrong
workspace root because of a duplicate lockfile in the parent folder. Fixed by
pinning `turbopack.root` in `next.config.ts`.

### 2.2 Titles & descriptions
- All routes had unique titles/descriptions (good baseline).
- **Fixed:** `/contact` inherited the homepage title/description → created
  `app/contact/layout.tsx` with its own metadata.
- **Fixed:** `/admin` and `/admin/login` inherited homepage metadata → new
  `app/admin/layout.tsx` sets "Admin | Atlas Screening" + `noindex,nofollow`.
- Root description rewritten to be FCRA-safe (see §5).

### 2.3 Headings
- Only the homepage + 404 had an H1 (per rendered crawl, inner pages used h2
  heroes). **9 routes rendered with no H1**: /client-certification, /compliance,
  /dispute-resolution, /privacy, /terms, /trust(redirects), /services,
  /resources/cost-calculator, /resources/package-recommender.
- **Fix:** `SectionHeader` gained an `as?: "h1" | "h2"` prop; page heroes
  (LegalPage + 3 tool/services heroes) now render H1. Every route now has exactly
  one H1. Section headings remain H2 — hierarchy preserved.
- Homepage H1 contains the animated word-flip duplicates ("Trust. Trust.") —
  visual only; noted, not changed.

### 2.4 Images
- All 16 `<Image>`/`<img>` tags carry alt text (0 missing) — strong baseline.
- Hero video `banner.mp4` (47 MB) is **not referenced anywhere in app code**
  (orphan asset) — candidate for deletion or compression (see §7).

### 2.5 Structured data — implemented
| Schema | Placement |
|---|---|
| Organization + WebSite | Root layout (all pages) — name, url, logo, sameAs, contactPoint, FCRA-safe description |
| Service + BreadcrumbList (+ FAQPage) | All 9 service pages via new `ServiceJsonLd` component |
| FAQPage | /faq (11 Q&As) |
| BlogPosting | All blog post pages (headline, image, datePublished, author, publisher) |

All JSON-LD blocks validated (parse-checked in the crawl).

## 4. Indexation & crawl control

- **robots.txt** (new): `Allow: /`, `Disallow: /admin`, `Sitemap:` line.
- **/admin**: `robots: { index: false, follow: false, nocache: true }` in
  `app/admin/layout.tsx` (covers /admin/login + all panel routes).
- **/trust**: intentionally redirects to /compliance (`redirect()` in page) —
  excluded from sitemap, correct behavior.
- **canonical**: root layout sets `alternates.canonical: "/"`; blog posts set
  per-post canonicals; all routes emit canonical links (verified in crawl).
- **next.config.ts**: added `turbopack.root` pin (fixes dev staleness; the
  workspace-root misdetection was silently serving stale routes).

## 5. FCRA compliance pass on metadata & copy

Per the FCRA-AI-PROMPT-STANDARD gate (§4), the following were flagged and fixed:

| Location | Before (overclaim) | After |
|---|---|---|
| Root description | "fast, accurate employment background checks … education verification, drug testing" | "FCRA-compliant employment background checks — criminal records, identity verification (SSN trace), employment verification, and tenant screening" (also drops services the site doesn't offer) |
| /about description | "need accurate decisions fast" | "need defensible, compliant screening decisions" |
| /services | "Instant turnaround — Results typically return in under 60 seconds" | "Fast database results — National database hits typically return in under a minute; most county searches complete the same day" |
| /services/ssn-trace | "Instant turnaround / Traces return in under 60 seconds" | "Fast turnaround / Traces typically return in under 60 seconds" |
| /services/sex-offender-registry | "Instant results with full match detail" | "Fast results with full match detail" |
| /how-it-works | stat "100% FCRA-compliant by design" | flagged for counsel review (kept; see §8 note) |
| FAQ | "Instant database searches: Same day" | kept — already qualified ("Some results may require additional verification…") |

**Bug fixed:** masked `tel:+191\*\*\*\*7712` hrefs on /compliance, /privacy,
/dispute-resolution, /terms → `tel:+19172757712`.

**Resilience fix:** `getPostBySlug` now falls back to static seed posts when
Supabase returns nothing, so blog routes can't 404 in production if the DB is
empty/unreachable (the list already had this fallback; the detail route didn't).

## 7. Recommendations backlog (not changed — deliberate)

1. **Compress/delete 47 MB `banner.mp4`** and re-encode hover `.mov` files to
   webm/mp4 (biggest single page-weight lever).
2. **Verify social profiles** — footer links to LinkedIn/X/Facebook/Instagram
   assumed to exist; confirm handles match and link to live pages (they feed the
   Organization sameAs schema).
3. **Analytics/search console** — connect GA4 + Google Search Console +
   Bing Webmaster; submit the new sitemap on launch.
4. **Blog content depth** — posts have no H2 subheadings (paragraph-only body);
   adding structured subheadings improves featured-snippet eligibility.
5. **"100% FCRA-compliant by design" stat** on /how-it-works — recommend
   counsel sign-off or rephrase to "FCRA-compliant by design" (removes the
   percentage framing).
6. **Heading hierarchy on blog bodies** — if post bodies gain H2s, keep exactly
   one H1 (already the case).
7. **HTTP→HTTPS + apex→www policy** — confirm canonical host (atlasscreening.com)
   is what the DNS serves and 301s are in place at the host/CDN layer.
8. **Hreflang** — not needed (single en-US site) unless a localized version ships.
